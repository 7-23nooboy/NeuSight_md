## 4. 关键观察与根因分析

### ✅ 准确范围: Water 32-1024 atoms (误差 12-15%)
- 实测 latency 几乎恒定 (~5.9ms)，说明完全被 overhead (CPU dispatch) 主导
- overhead 模型用 `n_kernels × 17μs` 估算 CPU pipeline = 5.4ms，加上 autograd = 6.7ms
- 与实测匹配良好，略偏高

### ⚠️ 问题1: Copper 单类型体系高估 35-41%
- **根因**: overhead 模型的 `FRAMEWORK_KERNELS["se_e2_a"]["base"]=250` 是根据 water (2 types) 校准的
- Copper 只有 1 type，框架层面的 type dispatch kernel 更少
- 实测 copper ~4.7ms vs water ~5.9ms，差 1.2ms → 单类型确实更少 overhead
- **修复方向**: `per_type` 系数应更大，或 base 应更小

### ❌ 问题2: 大原子数 (2048+) 严重低估
- **根因**: MLP_WAVE compute predictor 预测 2048 atoms = 2.17ms，但实测 wall time 暴涨到 11.8ms
- 实测 2048 atoms 时 GPU 计算不再被 CPU dispatch 掩盖，开始成为瓶颈
- MLP_WAVE 预测的 compute 增长 (线性) 远慢于实际增长 (可能是超线性，因为 neighbor list 操作)
- **修复方向**: MLP_WAVE 对大 batch Linear/BMM 的预测需要重新校准

## 5. 预测器适用范围建议

| 原子数范围 | 原子类型数 | 预期精度 | 建议 |
|-----------|-----------|---------|------|
| 32-1024   | 2+ types  | **±15%** | ✅ 可直接使用 |
| 32-1024   | 1 type    | **±40%** | ⚠️ 需校准 overhead 中 per_type 参数 |
| 2048+     | 任意      | **>40%** | ❌ compute 预测失准，需重新训练 MLP |

---

## 6. 后续改进优先级

1. **[高] 校准 per_type overhead**: 收集 1/2/3 类型体系的 profiling 数据，拟合更准确的 per_type 系数
2. **[高] 大原子数 compute 预测**: 分析 MLP_WAVE 在大 batch 下的预测偏差，可能需要增加训练数据
3. **[中] 训练 overhead MLP**: 用 {atom_count, num_types, sel, force} → overhead 的数据训练小 MLP
4. **[低] 更多模型类型**: 测试 DPA-1 (se_atten) 模型的精度
